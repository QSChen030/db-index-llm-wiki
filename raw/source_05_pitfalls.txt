[原始筆記 05] 索引失效常見原因與維護成本分析
建立了索引不代表查詢一定會走索引，以下三種常見寫法會導致索引失效：
1. 對索引欄位使用函數或運算：例如 WHERE YEAR(created_at) = 2026 或 WHERE id + 1 = 100，引擎無法直接拿未運算的鍵值去 B+ Tree 比對。
2. LIKE 查詢以萬用字元開頭：例如 WHERE name LIKE '%順'，B+ Tree 只能從字串最左邊的字元開始比對前綴，前導 % 會破壞前綴順序。
3. 違反最左前綴原則。
此外，索引並非越多越好：每多建一個索引，就多維護一棵 B+ Tree。當執行 INSERT、UPDATE、DELETE 時，資料庫除了寫入資料本身，還必須同步更新所有相關 B+ Tree 的節點結構與指標，會顯著降低寫入效能並佔用額外磁碟空間。
